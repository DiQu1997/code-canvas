# 研究型预览地图（preview 画布）规格 v0.1

面对陌生大仓库的第一张图。**不是文件夹地图**——分区是 agent 研究后
划出的**逻辑组**（可横跨目录、可只占目录一角），标注是研究结论，
故事线路是有依据的推荐。深潜画布（真实代码）由读者从线路点单。

## 研究规程（产 JSON 之前必须完成）

1. 读 README / docs 里的架构自述；有 ARCHITECTURE/design 文档必读
2. 跑 `python3 extract.py <包根> --out /tmp/inv.json` 拿全量函数清单，
   或 `preview.py` 拿目录摘要——这些是**研究材料，不是答案**
3. 抽查每个候选组的 2-3 个核心文件（读真实代码，不是只看名字）
4. 形成一段整体理解（这仓库是什么、怎么分层、数据怎么流），写进报告

## 分区（logical group）

- 5-9 个，**按概念划分不按目录**：一个目录可拆进多个组（v1/ 里调度与
  KV 管理是两个概念体），一个组可跨多个目录（"请求生命周期"横跨
  entrypoints 与 engine）
- 每个分区卡（`kind:"district"`）：
  - `name`：**概念名**（如 "调度与批组装"），不是路径名
  - `role`（≤6 字）+ `role_color`：服务入口 #0969da / 核心机制 #bf8700 /
    模型与执行 #8250df / 硬件加速 #d1242f / 基础设施 #1a7f37 / 配套 #57606a
  - `oneliner`（≤40 字）：研究得出的定位，不是目录描述
  - `stat`：**构成**——涉及哪些目录/文件 + 约行数（如
    "v1/core + v1/sched · 约 3.1 万行"）
  - `frac`：体量比例 0-1（条形图）
  - `highlights`：3-5 个**真实存在**的关键类/函数名（研究中核实过）
  - `file`：主要路径（点卡跳转用）
- 布局：`band` 按架构层（入口→核心→执行→底座），`col` 组内排开，≤5 列

## 故事线路（route）

- 3-6 条，每条 = 读者值得走的一次深潜主题
- `wires`：`kind:"route"`、`route:0-4`（五色），相邻站点两两连线
- 每条一个 step：`focus` = 站点序（即阅读序，渲染器自动标 ①②③）、
  `wires` = 本线路段、`caption` = pitch（≤70 字，为什么值得走）、
  `ask` = 交给深潜生成器的主题句（≤50 字）
- 总览 step（第 0 步）：`fit:true`，`wires` = 全部线路段（地铁图全览），
  caption 教读图

## 硬约束

- meta.mode: "preview"；validate 必须 0 ERROR
- highlights 里的名字必须在仓库里真实存在（抽查核实）
- 分区如果和目录一一对应，说明研究没做——至少要有一处拆分或合并
  体现概念判断；做不到时在报告里说明为什么（小仓库可能确实一一对应）
- 交付报告：整体理解一段、每个分区的构成依据、线路推荐理由
