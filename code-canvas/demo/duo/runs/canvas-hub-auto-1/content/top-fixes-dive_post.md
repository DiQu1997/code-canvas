# 顶层需要改的地方（来自 dive_post 这一趟，以 manuscript-dive_post.md 为准）

1. **部件 `post` 的说明卡，「容易看错」第 1 条**
   - 原话：「embed / check_refs 失败**不会**拦下画布：embed 失败只是画布没上下文；check_refs 是「删掉假依据」而不是拒收。」
   - 问题：「embed 失败只是没上下文」不准。embed 一张都没嵌成时 exit 2 被吞、不写 `files`，validate 的名字核对语料只剩卡代码，原本靠 `files` 全文通过的黑盒 / 变量会变成 ERROR → rc=4（底稿 §2.5「一个间接的“拦”」，例子 `is_finished`）。
   - 建议：「embed / check_refs 自己从不拦下画布（退出码被 `;` 吞掉）；但 embed 一张没嵌成时，validate 核名字只剩卡代码可查，可能因此判「编造」→ rc=4。」

2. **源码页 `src_post`，批注 `at((627, 628))`**
   - 原话：「embed 同样接 `;`：嵌入失败画布照样往下走，只是没有上下文。」
   - 问题：同第 1 条（底稿 §2.5）。
   - 建议：「……照样往下走；但没了 files，后面 validate 的名字核对会更严。」

3. **部件 `post` 的说明卡，「怎么设计的」第 1 条**
   - 原话：「`cp` 进库 + `render.py` 出 html + 写 `.src.json`，任一步失败 → rc=6。」
   - 问题：写来源记录那段是 `{ printf …; :; }`，末尾 `:` 让它永远算成功；rc=6 只可能来自 cp 或 render（底稿 §2.6）。
   - 建议：「cp 或 render 失败 → rc=6（来源记录那步永远算成功）。」

4. **部件 `lib` 的说明卡，「容易看错」**
   - 原话：「render 失败时 json 已经拷进来了，库里会剩一个只有 json 的半成品（列表只认 html，所以看不见）。」
   - 问题：只对「首次生成」成立；同名画布已存在时，是 json 已换新、html 还是旧的（新旧不一致）（底稿 §2.6）。
   - 建议：补一句「同名画布已存在时，json 换成新的、html 还是旧的」。

5. **推演第 7 步「服务端收尾：再查一遍」**（一致性，不算错）
   - 原话：「check_refs：这份旧格式画布没有 refs，核 0 条 ✓」。
   - 情况：对仓库里的旧格式样板这是对的；但 dive_agent 和 dive_post 两份底稿都设定 agent 写了 **6 条依据**（dive_post 底稿 §3 主线第 3 步【设】「依据核对：6 条，通过 6，剔除 0」）。下层推演按 6 条走，并在第 1 步说明了样板其实没有依据。
   - 建议（可选）：改成「check_refs：设 agent 写了 6 条依据，6 条全过（仓库里的旧格式样板其实没有 refs）」，与两个下层对齐。
