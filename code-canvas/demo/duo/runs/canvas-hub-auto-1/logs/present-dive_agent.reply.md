## 1. 画了什么、为什么这么取舍

**8 个框**：提示词 → 规程 SKILL.md → agent 的判断（`meta.judgment`）→ canvas.json；另有三个框围着它：结构提取（可选）、自查工具、新读者；最后是退出。

**9 条线**，里面有两条回到 agent：
- 「自查工具 → agent」，线上写「输出 + 退出码」；
- 「新读者 → agent」，线上写「报告，自己读」，画成虚线。

底稿里最该记住的三点就画在这几处：
- 契约「不可商量」不等于机器会拦；
- 什么时候「做完了」没有机器判据，打印的 DONE 没有任何代码读；
- 新读者挑出的问题不会自动回到 agent 手里。

**推演**：接着顶层那一单（nano-vllm +「讲讲调度器怎么工作」，同一个 job id、同一个缓存路径）走 10 步。数全用第二份底稿 §3 的设定值：
- 判断 1 答「深潜，收窄到调度」；
- 主角 `Sequence`；
- 第一次 validate 报 `1 errors`；
- check_refs「6 条，通过 5，剔除 1」；
- 新读者报告「③ 的 -1 没解释」，agent 补一条注释、记 1 轮 `reader_rounds`。

框里的小图跟着每一步变。lead 里写明了这是设想的一种走法。

**取舍**：
- **没再做第三层机器图。** 新读者、结构提取、工具环拆开看，都是从头读到尾的一个函数或一段规则，按舞台说明 8.2 节直接落到源码页。6 个源码页是：提示词、8 个判断（批注里写例子的答案）、extract、自查工具、reader_check、契约和谁在执法。
- **不画「仓库缓存」框。** 顶层已经有它；放进来手机版会多出无法避开的交叉线。「产物在工作目录、不在缓存」这件事挪进了 canvas.json 框的「易混点」。
- **不讲**：`--merge` 增量协议（新生成用不到）；canvas.json 里卡、线、步的样子（那属于「浏览器排版」那个框，不在 agent 里面）。
