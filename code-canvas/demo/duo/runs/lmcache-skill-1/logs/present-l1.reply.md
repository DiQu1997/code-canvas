## 4. 推断和缺的事实

**标成推断的「为什么」**：
- 门面只翻译、不存状态的好处；
- 整批分配的好处；
- 过期暂存交接的好处；
- 过滤器不拿 L1 全局锁、可能和监听回调反序互等；
- `cb8b1c04` 之前淘汰配额会浪费（从提交标题反推）；
- 池里全是被锁住的对象时 OOM 会一直持续；
- 1 s 心跳之内写满池子就只能 OOM。

**一处观点**：OOM 可以只存前 2 块（底稿【观点】）。

**底稿也没查到的**（我止步于说明卡，没有补）：300 s / 600 s 这两个数为什么这么定；为什么 `TTLLock` 用 C++ 实现；为什么锁到期后计数重置为 1；为什么淘汰是 1 s 轮询；为什么按 key 个数而不是按内存算 20%。

**「池里只剩 2 个槽」是我补设的值**（为了把底稿的 OOM 例子放进推演），推演里标了「设」，补设的理由写的是「一秒内写入涌进来」。

**顶层**有 3 处说法不准，已经写进 `content/top-fixes-l1.md`，顶层文件没动：
1. 查 L1 时说「逐个 `reserve_read`」，实际是按行批量调的；
2. 「淘汰 20%」没说清是按 key 个数，不是按内存；
3. 「L1 满了不会卡住」没说清 OOM 是整批的，也不会当场淘汰。
