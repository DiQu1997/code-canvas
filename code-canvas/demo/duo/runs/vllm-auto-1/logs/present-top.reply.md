## 4. 推断和不确定的地方
- **标了「推断」的「为什么」**：
  - 生成器惰性提交的好处。
  - 拆两个进程是为了避免抢 GIL（底稿 §8 已说明没有出处）。
  - stop 串放在前端判的原因。
  - 单槽信箱的好处。
  - 用 ROUTER 是为了 DP>1 做准备。
  - `add_request_async` 只等发送完成、不等引擎处理。
  - 判停和释放 KV block 放在同一处的好处。
- 「调度器状态只被主线程改、不用加锁」我标成了推断。底稿其实说有注释明说（`core.py:1277-1279`），可以升级成「注释」，我没有去核对原文。
- **底稿里缺、我需要的事实**：eos 命中时 `batch_queue` 里已经排好的那一步怎么处理（多算的 token 怎么丢）。如果只能转给研究员一个问题，就问这个。
- **底稿锚点的小出入**：底稿说 `run_busy_loop` 在 `core.py:1763`，HEAD 上的定义在 1814，1763 大概是调用它的地方。我的源码页用的是 1814–1823。
