# 机器图舞台：写 content_scene.py（Redis 淘汰）时碰到的问题

都已绕开，没有改舞台代码。

1. **g_cells 放不下就换行，没有紧凑模式。** 候选池 7 个格子放进 180 宽的框会折成两行，「排成一排、按分数从低到高」这个直观印象就没了。
   复现：`g_cells([cell('c','5s'), cell('a','12s'), cell('b','340s'), cell('x','600s'), cell('e','860s'), cell('d','2h'), cell('g','2.5h')], right='+9 空')`，框宽 180。
   想要的是：固定 N 个槽位的窄条（比如 16 格，空格也画出来），值写小字或写在槽下面。

2. **字数预算取桌面和手机两套框宽里较窄的那个。** 手机上为了让两个框并排只能给 100–150 宽，桌面上同一个框宽 190，
   框底那句话也只能按 100 宽来写（say ≤ 12）。想要：两套布局各算各的预算，或者允许手机版单独给 `msay`。

3. **连线是不避障的贝塞尔曲线。** 手机竖排时，回头的长线（`gate → sample`、`del → buf`）只能靠 `mfs/mts` 选边、
   在左右留出 70–80 像素的空沟，标签再用 `mlp` 手放进沟里；沟窄，所以这几条线的 why / trap 只能写三四个字。
   想要：可以给一条线指定一两个折点（`via=[[x, y], …]`）。

4. **手机推演时，一步点亮的东西相距太远就只看得到一部分。** 第 6 步同时点亮「删除并广播」（y≈910）和
   「待发缓冲」（y≈8），截图里推演条把下面那个挡住了，读者只看到了缓冲那头。想要：focus 能指定「镜头对准哪一个」。

5. **线上的角标 `n` 和框的角标长得一样。** 两套编号放在一起（框 ①–⑦，线 ①–⑥）读者会以为是同一个序列，所以最后线上都没标 `n`。
