# 机器图（scene）作者指南

顶层那一页换成一张**机器图**：部件（框）+ 连线 + 一段可选的逐步推演。读这份 + `cv.py` 末尾「机器图」一节就够写。
下层各页不动（仍是 `content_*.py` 的内容，写法见 WRITERS.md）。

## 0 读者拿到的是什么

- **一张图**：每个部件是一个框（名字 + 中间一块小图 + 框底一句话），部件之间是带短标签的连线。
- **点任何一个框或一条线 → 展开它的说明卡**，固定四栏：**这里是干什么的 / 怎么设计的 / 为什么这么设计·好处是什么 /
  容易看错的地方**（最后一栏可空）。桌面是右侧抽屉，手机是底部抽屉；卡里可以翻「上一个 / 下一个」。
- **三个图层开关**：主流程 / 为什么 / 易混点。切图层时，框底那句话和线上的字跟着换（`say` → `why` → `trap`）；
  没写 `why` / `trap` 的框和线在那个图层下变淡。
- **▶ 推演**：拿一个具体例子一步一步走。每一步点亮几个框和线，下面两栏：**发生了什么**（带具体的值）/ **为什么这样**。
  一步可以把某个框中间的小图换成新的值。
- 有 `to` 的框 / 线，说明卡底部有「钻进去看」的入口，飞到下层那一页。

图上只放得下短句，**讲清楚的活在说明卡里**：卡是从高处讲「这一块在整台机器里干什么、怎么设计的、为什么这么设计」，不是贴代码。

## 1 规矩

- 你只写 `content_scene.py`。**不许改** `cv.py / build.py / template*.html / shot*.js`，也不改别的 `content_*.py`。
- 发现框架 bug 或缺功能：写到本目录 `framework-issues-scene.md`（现象 + 最小复现），自己先绕开。
- 内容里**不写代码正文**；引文 `q` 必须从仓库原文照抄（不翻译），构建会核对；`文件:行号` 和提交哈希也会核对。
- 每个「为什么」都必须是一条带等级的 `note(等级, 文字, q=, ref=)`。等级：`注释 / 提交 / 文档 / 测试`（要给 `q` + `ref`）、
  `推断`（自己推出来的，不用依据）、`观点`。**没证据就标「推断」，不要硬找依据**。
- 不要安装任何东西；不要 `cd` 进被研究的仓库，也不要在里面跑任何脚本。

## 2 文件约定

```python
from cv import *

def root(base):                 # base = 原来的顶层节点（title / lead / children 都在）
    base['lead'] = '一两句：这张图回答什么问题'
    base['blocks'] = [scene(...)]   # 可以再加 p(...) / note(...)，但一屏之内以图为主
    return base                  # children 别动：下层各页靠它挂着
```

## 3 帮手（签名以 cv.py 为准）

| 帮手 | 用来 |
|---|---|
| `scene(w, h, parts, wires, steps=None, mw=None, mh=None, groups=None, cap=None)` | 整张图。`w/h` 桌面画幅，`mw/mh` 手机画幅 |
| `part(id, name, d, m=None, code=None, kind='act', n=None, glyph=None, say=None, why=None, trap=None, card=None, to=None)` | 一个部件。`d` / `m` = 桌面 / 手机的 `[x, y, w, h]` |
| `wire(id, f, t, label, n=None, why=None, trap=None, card=None, to=None, ml=None, fs=None, ts=None, mfs=None, mts=None, lp=None, mlp=None, cls=None)` | 从部件 `f` 到 `t` 的线；`f == t` 画成回环 |
| `card(does, how, why, traps=None)` | 说明卡。每栏是一条或一组条目；条目 = 一段字，或 `note(...)`。`why` 栏必须是 `note` |
| `beat(title, what, why=None, focus=None, state=None)` | 推演的一步。`focus` = 点亮的部件 / 连线 id，**第一个是镜头的主角**（屏幕装不下全部时，保证第一个露出来，后面的按顺序、装得下才一起入镜；所以把这一步最该看的那个框放第一个）；`state = {部件id: 新小图}`：从这一步起那个框换成新小图，一直保持到后面再换；给 `None` = 从这一步起不画小图 |
| `group(label, d, m=None)` | 虚线分组框（把几个部件圈成一个子系统），传给 `scene(groups=[...])` |

- `kind`（决定框的颜色）：`act` 动作 · `store` 存着的数据 · `ext` 外部来的 · `bg` 后台 / 旁路 · `gate` 判断 · `out` 结果。
- `n`：角标（`'1'` `'2'`… 标主流程的顺序；线上也能标）。`code`：代码里的名字，等宽小字。
- `to`：能钻进去的下层节点 id（或列表）。**有哪些 id，构建输出末尾会列出来**；标「未展开」的是空页，别指过去。
- 线的 `fs / ts`：从哪条边出、进哪条边（`'l' 'r' 't' 'b'`），不给就按两个框的相对位置自动挑；`mfs / mts` 是手机版。
  `cls='dash'` 画虚线（旁路 / 异步 / 偶尔才发生）。`ml` 是手机上的短标签。
- 文字迷你语法（说明卡条目、`note`、`beat` 的 what / why、`lead`、`cap` 里可用）：`` `src/x.c:12-34` `` 锚点（可点开看原文）、
  `` `c:哈希` `` 提交、别的反引号 = 行内代码、`[[节点id|文字]]` 内链、`**粗体**`。
  **框底那句话和线上的字是短句，尽量别放锚点**（放不下）；依据放到说明卡里。

### 小图（glyph）：框中间那一块，把「里面装着什么 / 现在是什么值」画出来

| 帮手 | 画出来 |
|---|---|
| `g_cells(cells, left=None, right=None)` | 一排格子，`cells` 用 `cell(k, v, s)`；`s`：`'new'` 新进 / `'out'` 被挤掉 / `'pick'` 被选中 / `'mv'` 挪动过 / `'ghost'` 残影 / 不给 k = 空格。两头可标小字 |
| `g_gauge(used, limit, total=None, label=None, unit='')` | 一根量条：当前值、红线；超过红线的部分画红 |
| `g_list(rows, on=None)` | 几行短字，`on` = 高亮哪一行（下标或下标列表） |
| `g_kv(rows)` | 几行「名字 → 值」：`[(名字, 值), …]` |
| `g_checks(rows)` | 几行判断：`[(文字, 状态), …]`，状态 `'ok'` 过 / `'no'` 不过 / `'skip'` 没走到 / `None` 还没判 |
| `g_text(big, small=None, tone=None)` | 一个大字的值 + 一行小字；`tone`：`'ok'` 绿 / `'run'` 黄 / `'fail'` 红 |
| `g_raw(html)` | 万不得已的口子：自己给一段 HTML / SVG，不过校验 |

小图里的值要**和推演用的例子是同一套数**：读者按 ▶ 时看到的是这些值在变。

## 4 字数预算（超了构建会 WARN；宽度单位：汉字算 1，其余算 0.5）

| 位置 | 上限 |
|---|---|
| 框底 `say` / `why` / `trap` | `2×cap` / `2×cap−3` / `2×cap−2`，其中 `cap = max(4, (框宽−22)//13)`，框宽取桌面、手机两套里**窄的那个**（框宽 150 → say 最多 18） |
| 线上 `label` / `ml` | 12 |
| 线上 `why` / `trap` | 18 |
| 说明卡的一条纯文字条目、`beat` 的 `what` | 220 字（再长就拆成几条） |

## 5 坐标怎么排（都是踩过的坑）

两套坐标各排各的：桌面是横向的大图，手机是竖着的长图，**不要把桌面版按比例缩一下当手机版**。

**桌面**（宽 1220，高 460–520 时在 1440×900 的屏上能一屏看全；主流程从左到右。**高超过 520 构建会 WARN**：全景会被整体缩小，630 高时约 0.8 倍。推演时镜头只框图本身，会比全景大一些）
- 有小图 + 两行字的框，高度 **≥ 120–130**（判断框里三四行的 `g_checks` 要 150 左右）；没有小图的 ≥ 80。
  **按最挤的图层留高度**：「为什么」那一行前面带一个等级小标，通常要占两行。
- 左右相连的两个框，中间留 **≥ 120–150**：线上的字会自动折行去适应这个空隙，空隙越小字折得越高。
- 上下相连的两个框，中间留 **≥ 56**。

**手机**（`mw=340`，高度不限，读者会上下拖）
- **竖着排**：主流程从上到下，一行一个框（或者两个互不相连的框并排）。上下相连的框之间留 **≥ 56–70**。
- **左右并排又有线相连**的两个框，中间至少留 **80**（放得下标签的最小宽度是 64）。340 宽里这意味着两个框各只有 120 左右——
  只适合小图简单的框。放不下就改成上下排。
- 框宽 110 以下基本放不下 `g_gauge` / `g_cells`；这种小框用 `g_text` / `g_kv`，或者不放小图。

**线**
- 标签默认放在线的中段，并且会沿着线自动挪开去避让框和别的标签；实在避不开，用 `lp` / `mlp` 自己指定 `[x, y]`。
- 回环（`f == t`）从 `fs` / `mfs` 指定的那条边鼓出去 44，标签再往外放：**那一侧必须是空地**，并且离画幅边缘还有 ≥ 90。
- 一个框同一条边上有几条线时，接入点自动均分，不用管。线会绕不开挡在中间的框——那就调框的位置或换一条边出线。

## 6 构建与自检

```bash
python3 -I <本目录>/build.py <仓库路径> <本目录>/out_scene          # 产物：out_scene/scene.html
node <本目录>/shot_scene.js <本目录>/out_scene/scene.html <截图目录> --check   # 只做机械排版检查，几秒钟
node <本目录>/shot_scene.js <本目录>/out_scene/scene.html <截图目录>          # 完整：检查 + 交互 + 8 张截图
```

- 构建输出末尾看两样：`WARN N 条（只列机器图自己的）`（要清零，或逐条说明）和**可钻节点清单**。
  前面那一大段是下层各页的统计，与你无关。`BuildError` 会直接说哪个部件 / 连线的哪个字段不对。
- `--check` 在桌面和手机两种屏、三个图层、每一步推演下各量一遍，输出 `LAYOUT [桌面|手机] …（出现在哪些图层 / 步骤）`：

| LAYOUT 说 | 意思 | 怎么改 |
|---|---|---|
| 框里的小图放不下 / 小图被挤没 | 框太矮或太窄 | 把框加高（或加宽）；或换个更小的小图；或把框底那句话缩短到一行 |
| 框底那句话超过两行被截断 | 字太多 | 缩短，或把框加宽 |
| 名字一行放不下 | `name` + `code` 太长 | 缩短，或去掉 `code` |
| 线标签压在部件上 / 互相叠 | 两个框之间的空隙放不下标签 | 拉开两个框；换出线的边；手机上改成上下排；最后才用 `lp / mlp` |
| 线标签伸到画幅外面 | 标签离边缘太近 | 把框往里挪，或回环换一侧 |
| 连线从部件身上穿过 | 路上有框挡着 | 挪框，或用 `fs / ts` 换出入的边 |

  **改坐标时反复跑 `--check`（只出文字，不费钱），排到 0 条再截图**。截图是用来判断「这张图读者看不看得懂」的，
  不是用来找叠字的。
- 完整跑出的截图：`d1-overview`（桌面全景）`d2-why` `d3-trap`（另两个图层）`d4-card`（点开一张说明卡）`d5-step<N>`（推演中间一步）
  `p1-overview` `p2-card` `p3-step<N>`（手机）。加 `--steps` 每一步各截一张，加 `--dsf2` 出给人看的高清图。

## 7 一个能跑的小例子（与任何真实仓库无关，只示范写法）

```python
from cv import *


def root(base):
    base['lead'] = '一台自动售货机：先投币，钱够了才出货。图里每个框、每条线都能点开。'
    parts = [
        part('coin', '投币口', [40, 40, 220, 130], m=[8, 8, 200, 124], kind='ext', n='1',
             glyph=g_text('5 元', '刚投进来'),
             say='收钱，只认硬币', why='不找零，机器里不用备零钱', trap='不是先选货再投币',
             card=card('把顾客投的钱收进来。',
                       ['只认 1 元和 5 元硬币。', '投进来的钱立刻记到余额上。'],
                       [note('推断', '不做找零，机器里就不用备零钱，也少一种会坏的零件。')],
                       '顺序是先投币再选货，不是反过来。')),
        part('bal', '余额', [480, 40, 240, 130], m=[8, 196, 200, 130], kind='store', code='balance',
             glyph=g_kv([('已投', '5 元'), ('可乐', '3 元')]),
             say='记着已经投了多少', why='钱和货分开记，断电不丢账',
             card=card('记着这位顾客已经投了多少钱。', '就一个数字；每投一枚就加上去，出货就扣掉价钱。',
                       [note('推断', '钱和货分开记账：出货卡住时余额还在，可以退。')])),
        part('out', '出货口', [940, 40, 240, 130], m=[8, 390, 200, 124], kind='out', n='2',
             glyph=g_text('可乐', '掉下来了', tone='ok'),
             say='钱够了，货掉下来', trap='掉货不等于扣款成功',
             card=card('把选中的货推出来。', '余额够才转电机，转完再扣余额。',
                       [note('推断', '先出货后扣款：卡货时顾客不吃亏。')],
                       '货掉下来不代表账已经扣完，扣款在后面一步。')),
    ]
    wires = [
        wire('w_pay', 'coin', 'bal', '记到余额', n='1', why='先记账，后面才能判断',
             card=card('把刚投的钱加到余额上。', '每枚硬币加一次。', [note('推断', '先把钱记下来，后面每一步都只看余额这一个数。')])),
        wire('w_buy', 'bal', 'out', '够了就出货', ml='够了出货', n='2', why='只比一个数，不会算错', trap='不够不会出一半',
             card=card('余额够价钱时，通知出货口。', '只比较「余额 ≥ 价钱」。', [note('推断', '判断只有一个比较，最不容易出错。')],
                       '钱不够时什么都不出，不会出一半。')),
        wire('w_wait', 'bal', 'bal', '不够就等', fs='b', mfs='r', cls='dash', why='等下一枚，不清零',
             card=card('钱不够时原地等下一枚硬币。', '余额保持不动。', [note('推断', '不清零，顾客可以一枚一枚慢慢投。')])),
    ]
    steps = [
        beat('投进 5 元', '顾客投了一枚 5 元，余额从 0 变成 **5 元**。',
             note('推断', '先记账：后面判断够不够只看余额。'), focus=['coin', 'w_pay', 'bal']),
        beat('选可乐', '可乐 3 元，余额 5 元够了，货掉下来，余额剩 **2 元**。',
             note('推断', '先出货后扣款，卡货时不吃亏。'), focus=['bal', 'w_buy', 'out'],
             state={'bal': g_kv([('已投', '2 元'), ('可乐', '已出')])}),
    ]
    base['blocks'] = [scene(1220, 250, parts, wires, steps, mw=340, mh=522, cap='示例：自动售货机')]
    return base
```

这个例子构建 WARN 0、`--check` 排版问题 0。注意它的手机版：三个框从上到下，回环放在右侧空地。
